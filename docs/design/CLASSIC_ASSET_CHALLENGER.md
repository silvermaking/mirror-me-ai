## 플레이 장면 계약

### 시작 후 10초

시작 입력 뒤 100ms 안에 전투가 보인다. 플레이어가 오른쪽으로 세 번 피할 때마다 보스 몸에 방향성 있는 기억 명판이 하나씩 꽂히고, 세 번째 명판 뒤 한 개의 주홍 표적으로 연결된다. 표적이 굳은 뒤 플레이어가 왼쪽으로 대시해도 표적·연결선·드라이버 축은 움직이지 않는다. 드라이버가 빈 표적에 박히면 반동이 팔에서 몸통과 셔터로 전달되어 순백 코어가 열리고, 검 끝이 직접 닿을 때만 HP가 줄어든다.

### AI가 나를 학습했다는 순간

세 기억 명판의 방향과 연결선 종점, 주홍 LOCK 인장 중심은 같은 2D 바닥점을 가리킨다. 드라이버는 LOCK 동안 그 고정 축 위에서 장전되고 해결 프레임에만 끝이 인장 중심에 닿는다. HUD를 숨겨도 `내가 남긴 세 표본 → AI가 고른 한 좌표 → 그 좌표에 커밋한 공격`이 한 화면에서 이어져야 한다.

### 실패 후 바로 다시 하는 이유

게임 오버는 마지막 위험선·LOCK 표적·플레이어 종료점·보스 자세를 그대로 남긴다. 전장을 가리는 결과 카드는 쓰지 않고 “다음에는 반대로”처럼 다음 판에 바꿀 행동 하나만 표시한다. 1.25초 뒤 Enter 또는 Space부터 100ms 안에 다시 이동할 수 있어야 한다.

## 아트 문법

- 카메라와 화면 점유율은 `e63f7a0`의 `1280×720`, 중심 `640×404`, 투영 `1.03×0.77`을 기준으로 한다.
- 플레이어는 작은 코발트 망토, 밝은 얼굴, 화면에서 분리되는 검으로 읽힌다.
- 보스는 낮고 무거운 먹빛 몸통, 비대칭 상아 외피, 한쪽의 과장된 파일드라이버로 읽힌다.
- 기억은 정확히 세 개, LOCK은 한 개의 움직이지 않는 주홍 인장, 열린 코어는 화면에서 가장 밝은 순백색이다.
- 큰 명암 덩어리와 비대칭 실루엣을 먼저 만들고, 표면 장식은 320×180 판독을 방해하지 않는 범위에서만 쓴다.
- 위험선·대시 흔적·검 궤적·접촉 파문은 연속 Canvas 드로잉으로 남긴다.

## 액션 가독성 고도화

- 검격은 판정이 난 첫 프레임에 검 끝과 접촉점을 정확히 맞춘 뒤, 0.24초 안에 `접촉 → 45도 이상의 큰 절단 → 반동` 세 키포즈를 보인다. 플레이어 발점은 움직이지 않는다.
- 열린 코어는 먹빛 칼라 안의 순백 면과 바닥 반사로 외피에서 분리한다. `OUTSMART`는 셔터만 열고, 검 끝이 코어에 닿은 순간에만 압축·파문·파편이 함께 발생한다.
- 코어가 열린 뒤 첫 직접 타격 전까지 순백 바닥광과 세 개의 청록 화살이 플레이어 발에서 코어로 이어진다. 두 번째 직접 타격부터 셔터가 미리 오므라들고 황동 복귀 충격 둘레가 나타나며, 세 번째 타격에는 주홍 긴급 둘레와 바깥쪽 이탈 화살로 바뀐다. 이 표현은 `phaseTime`과 이미 확정된 타격 수만 읽는 렌더링이며 판정·노출 시간·피해를 바꾸지 않는다.
- 망토와 셔터에는 감쇠 스프링, 충격 파편에는 최대 12개의 결정적 탄도 운동을 적용한다. 이는 렌더링 전용 2차 운동이며 판정·좌표·HP를 읽거나 쓰지 않는다.
- 첫판 안내는 해답을 시작 화면에 모두 노출하지 않는다. EXPLORE 위험선이 실제로 생긴 뒤 `WASD`, LOCK이 굳은 뒤 `반대로`, 순백 코어가 열린 뒤 `J`를 전장 바닥에 한 단계씩 표시한다.
- Matter.js·Rapier 같은 별도 물리엔진은 사용하지 않는다. 현재 게임의 2D 충돌 진실을 복제하는 비용과 오차가 시각 반응의 이득보다 크기 때문이다.

## Boss Motion Pass

- 기억 명판은 즉시 출현하지 않는다. 첫 두 표본은 EXPLORE_RECOVER의 0.16초, 세 번째는 COMBINE 시작의 0.24초 동안 실제 회피 종료점에서 빈 슬롯으로 이동해 한 장씩 체결된다.
- 각 기억 명판에는 320×180에서도 방향이 남는 굵은 좌·우 화살을 새기고, 빈 슬롯은 반투명 받침으로 낮춰 기억 표본과 HUD 상자를 혼동하지 않게 한다.
- LOCK 시작에는 인장이 0.12초 동안 찍혀 굳고, 파일드라이버 끝은 표적에서 최소 16 logical px 떨어져 있어야 한다. 표적·연결선·드라이버 축은 이후 고정한다.
- PREDICTION은 같은 고정 축에서 `86px 후퇴 → 116px 장전 정지 → 8px까지 전진`한다. 320×180에서 파일드라이버 끝의 총 이동은 18 CSS px 이상이어야 한다.
- 해결 프레임에만 드라이버 끝과 LOCK 인장 중심의 오차가 1px 이하가 된다. OUTSMART는 `접촉 0ms → 지지팔 압축 0~55ms → 몸통 붕괴 35~165ms → 셔터·코어 85~180ms` 순서로 전달되며, 몸통은 비대칭으로 30px 이상 끌린다.
- 사건음은 별도 음악이나 음성 설명 대신 `기억 체결음 1/2/3 → LOCK 저음 → 장전 마찰음 → 빈 타격과 코어 개방 → 검격과 코어 접촉`을 각 상태 이벤트에 동기화한다.

## Animation Identity Pass

- 플레이어는 망토·몸통·반대팔·검팔·경계선 검의 authored 부품으로 조립한다. 절차형 몸과 검은 로컬 아트가 실패했을 때만 사용하는 fallback이다.
- 플레이어의 고정 전후 순서는 `망토 → 반대팔 → 몸통 → 검팔 → 검`이다. 대기·이동·대시의 검은 몸 중앙 세로선이나 등 뒤가 아니라 몸 앞 45도 가드이며, 320×180에서 검날이 몸 바깥으로 8px 이상 보여야 한다.
- 검격은 판정 결과를 늦추지 않는 contact-first 안무다. `접촉 0~48ms → 절단 48~168ms → 반동 168~240ms`의 세 자세에서 몸통 회전 차이는 0.35rad 이상, 망토의 역회전 차이는 0.2rad 이상이어야 한다.
- 보스의 지지팔은 상·하부 주철 관절로 연결하며 어깨·팔꿈치·지면 피벗을 공유한다. EXPLORE, LOCK, 헛공격에서 선과 원으로 대체하지 않는다.
- 코어는 먹빛 림·순백 면·금속 반응 핀으로 분리한다. 직접 타격에서만 `면 0ms → 핀 40ms → 셔터 75ms → 몸통 110ms` 순으로 충격을 전달한다.
- 플레이어 판정점·발점·접촉 표식·그림자 중심, 그리고 직접 타격의 검 끝·코어·충돌 표식은 각각 1px 이내에서 일치해야 한다.
- 모바일 상한은 로컬 SVG 다섯 개, steady drawImage 24회, impact 32회, DPR 1.5와 파편 12개다. 이 상한을 넘는 장식은 추가하지 않는다.

## 에셋 계약

- 전신 포즈 시트와 Blender/WebP atlas를 사용하지 않는다.
- 런타임 신규 자산은 보스 파츠, 드라이버 파츠, 플레이어 망토, 충격 파편의 편집 가능한 SVG 네 장으로 제한한다.
- 기존 `assets/2d/sprites/relics.svg`는 기억과 LOCK에만 재사용한다.
- 생성 검토 이미지를 자르거나 추적해 게임 배경·스프라이트로 사용하지 않는다.
- SVG는 외부 이미지·스크립트·필터·폰트를 포함하지 않으며 저장소 상대 경로로만 로드한다.
- 에셋이 로드되지 않아도 최초판 절차 드로잉으로 즉시 플레이되고, 판정과 입력은 멈추지 않는다.

## PASS

- 320×180 무문구 화면에서 플레이어, 보스, 위험, 기억 세 개, LOCK, 빈 타격, 열린 코어가 분리된다.
- 무성 8초 입력에서 `회피 세 번 → 기억 → LOCK → 반대 회피 → 빈 표적 헛타격 → 코어 노출 → 직접 검격`이 읽힌다.
- LOCK 인장 중심과 기억 연결선 종점은 고정되며, 해결 프레임의 드라이버 끝까지 화면 오차가 1px 이하다.

- 새 아트가 실패해도 최초판 fallback이 즉시 실행되고 기존 게임 테스트가 모두 통과한다.
- 최초판보다 입력 반응, 위험 판독, 타격 인과, 재도전 속도 중 하나라도 나빠지면 채택하지 않는다.
